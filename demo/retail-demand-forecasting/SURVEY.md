# Repository survey

## Overview

`demo/retail-demand-forecasting` is a daily SKU-level demand forecasting project for a
retail replenishment team. It forecasts `units_sold` per SKU 28 days ahead; the forecasts
drive store ordering, so over-forecasting creates waste and under-forecasting creates
stockouts. The dataset is synthetic (generated by `scripts/make_dataset.py`): 24 SKUs x
420 days of daily sales, 2024-01-01 through 2025-02-23, with weekly and annual
seasonality, promo uplift, price variation, and 6 of 24 SKUs deliberately intermittent.
The project sits inside the outer `parallel-autoresearch` CLI repository; paths below are
relative to `demo/retail-demand-forecasting/`.

## Models

- `models/seasonal_baseline.py` - **the production/incumbent baseline** (README: "the
  model currently used in production"). Seasonal-naive: each forecast day repeats
  `units_sold` from the same weekday one week earlier, walking back up to 8 weeks if that
  day is missing, with a trailing-28-day-mean fallback; forecasts clipped at 0. Run with
  `uv run python models/seasonal_baseline.py`. It backtests on the final 28 days (prints
  backtest WMAPE), then refits on full history and writes 672 forecast rows (24 SKUs x 28
  days) to `forecasts/next_28_days.csv`. `HORIZON = 28`.
- `models/arima.py` - candidate upgrade built by the data science team. Per-SKU
  ARIMA(1,0,1) (statsmodels `ARIMA`, `order=(1,0,1)`, `maxiter=50`) with six weekday-dummy
  regressors (Monday is the reference level). Falls back to the trailing-28-day mean when
  a series is all-zero, has fewer than 3 unique values, or fitting raises; forecasts are
  NaN-filled and clipped at 0. Run with `uv run python models/arima.py`. Same 28-day
  backtest, writes `forecasts/next_28_days_arima.csv`.
- `.autoresearch/task/seed/solution/train.py` - a faithful port of the seasonal-naive
  production model to the autoresearch runtime contract (reads env vars
  `AUTORESEARCH_TRAIN_DATA`, `AUTORESEARCH_REQUEST`, `AUTORESEARCH_OUTPUT`; writes a
  Parquet with exactly `sku_id`, `date`, `forecast`). This is the incumbent baseline the
  experiment harness scores: validation WMAPE 0.1357, holdout WMAPE 0.1384, bias near
  zero (per `.autoresearch/task/task.yaml`).
- `scripts/make_dataset.py` - not a model; regenerates the dataset (see Data).

## Data

- `data/sales_daily.parquet` - the raw sales history (generated, gitignored). Parquet,
  10,080 rows = 24 SKUs x 420 days, no nulls, exactly 420 rows per SKU (no date gaps).
  Columns:
  - `sku_id` (str): product identifier, `SKU_000`-`SKU_023` (the id column).
  - `date` (datetime64[us]): calendar day; range 2024-01-01 to 2025-02-23 (420 unique
    days, daily frequency).
  - `units_sold` (float64): units sold that day - **the forecast target**. Mean 40.31,
    median 36, max 186; 22.4% of rows are zero overall.
  - `promo` (int64, 0/1): 1 when the SKU was on promotion; 4.66% of rows.
  - `price` (float64): shelf price that day; range 4.59-94.57.
  - `category` (str): product category, `CAT_00`-`CAT_05` (6 categories).
  `SKU_000`-`SKU_005` are the intermittent slow movers (zero-sale share 83.6%-95.5% per
  SKU); the other 18 SKUs have no zero days and strong weekly seasonality. Regenerate with
  `uv run python scripts/make_dataset.py` (`SEED=42`, `N_SKUS=24`, `N_INTERMITTENT=6`,
  `N_DAYS=420`).
- `forecasts/next_28_days.csv` and `forecasts/next_28_days_arima.csv` - model output
  (written on each run, gitignored, not currently present).
- `.autoresearch/task/` - harness-created splits of the same history (gitignored):
  - `seed/data/train.parquet`: 8,736 rows, 2024-01-01 to 2024-12-29 (364 days x 24 SKUs),
    same six columns as above. This is the only split experiment agents can see.
  - `private/validation.parquet`: 672 rows, 2024-12-30 to 2025-01-26 (28 days x 24 SKUs),
    columns `sku_id`, `date`, `units_sold`. Sealed from agents.
  - `private/holdout.parquet`: 672 rows, 2025-01-27 to 2025-02-23 (28 days x 24 SKUs),
    columns `sku_id`, `date`, `units_sold`. Sealed from agents.
  - `seed/forecasts.parquet`: 672 rows of incumbent baseline forecasts over the holdout
    window (2025-01-27 to 2025-02-23), columns `sku_id`, `date`, `forecast`.

## Evaluation

- In-repo (both `models/*.py`): single backtest window - hold out the final
  `HORIZON = 28` days of history (`cutoff = last_day - 28 days`), forecast those dates per
  SKU, merge with actuals on (`sku_id`, `date`), and score WMAPE =
  `sum(|forecast - actual|) / sum(|actual|)` (identical `wmape()` in both files). Horizon
  is 28 daily steps; there is no rolling-origin or multi-window backtest. Each script then
  refits on the full history and forecasts the next 28 days after the data ends.
- Harness (`.autoresearch/task/task.yaml`, goal "reduce wmape"): primary metric `wmape`
  (minimize); secondary metrics `mape`, `rmse`, `bias_pct`, `runtime_s`; guardrail
  `runtime_s<=600`. A protected evaluator scores a 28-day validation window (2024-12-30 to
  2025-01-26) and a later hidden 28-day holdout (2025-01-27 to 2025-02-23), with
  `id_column: sku_id`, `date_column: date`, `target_column: units_sold`. Agents may edit
  only `solution/`; 3 agents per round, 4 rounds, per-agent timeout 1200 s. Incumbent
  (seasonal-naive) reference scores: validation WMAPE 0.1357, holdout WMAPE 0.1384, bias
  near zero. One research session exists at `research/001-reduce-wmape/` (round 1
  proposed: global Tweedie GBM, SBA routing for intermittent SKUs, zero-shot Chronos-Bolt;
  not yet executed).

## Dependencies

From `pyproject.toml` (requires-python `>=3.12,<3.14`):

- `numpy>=2.0` - array math in both models and the data generator.
- `pandas>=2.2` - data handling everywhere.
- `pyarrow>=17` - Parquet I/O.
- `statsmodels>=0.14` - `ARIMA` in `models/arima.py`.
- `xgboost>=2.1` - declared but not imported by any current script (headroom for tree
  experiments).
